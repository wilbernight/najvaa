# نجوا — بسته‌ی کامل نصب

این پوشه همه‌ی کدهای چت نجوا و پنل مدیریت را دارد، به‌اضافه‌ی `install.sh` که روی یک سرور **دبیان ۱۲ یا ۱۳** همه‌چیز را خودکار نصب می‌کند: همان کارهایی که روی سرور فعلی انجام شد، از جمله DNS و تنظیمات کلادفلر.

## محتوای بسته

| مسیر | چیست |
|---|---|
| `install.sh` | نصب‌کننده‌ی تعاملی (سؤال می‌پرسد، بعد همه‌چیز را خودش انجام می‌دهد) |
| `chat/public/` | خود سایت چت (app.js، فیلتر صدای زنانه، فونت، …) |
| `chat/server/relay.js` | رله‌ی «کور» که فقط متن رمزشده می‌بیند و نگه می‌دارد |
| `chat/voicefx-src/` | سورس دو موتور تغییر صدا و اسکریپت ساخت `voicefx-worklet.js` |
| `system/najva-ddns.py` | به‌روزرسانی خودکار IP در DNS کلادفلر (IPv6 و/یا IPv4) |
| `panel/` | پنل مدیریت (Laravel + Nova) آماده‌ی اجرا، بدون هیچ رمز یا داده‌ای |
| `android/` | اپ بومی اندروید (Kotlin + Jetpack Compose)؛ متصل به رله‌ی نجوا |

هیچ رمز، توکن، گواهی یا داده‌ی چتی داخل این بسته نیست؛ نصب‌کننده همه را روی سرور جدید می‌سازد.

## اپ اندروید

نسخه‌ی بومی اندروید در پوشه‌ی `android/` است: Kotlin، Jetpack Compose (Material 3)، راست‌به‌چپ، فونت وزیرمتن و ارقام فارسی. اپ به همان رله‌ی نجوا در `https://najvaa.xyz` وصل می‌شود و با نسخه‌ی وب کاملاً هم‌پروتکل است: همان اتاق را می‌توان هم‌زمان در مرورگر و گوشی باز کرد، تاریخچه‌ی رمزشده هم‌گام می‌شود و پیام زنده، پاسخ، واکنش، ویرایش، حذف برای هر دو، حذف خودکار، فایل، عکس، ویدیو و پیام صوتی بین هر دو رد و بدل می‌شوند. تماس صوتی/تصویری (WebRTC) در این نسخه نیست.

جزئیات طراحی و مدل امنیتی در `android/DESIGN-fa.md` آمده است. خلاصه:

- **یک رمز برای برنامه، یک گاوصندوق برای هر اتاق.** رمز برنامه با PBKDF2-HMAC-SHA256 (۳۱۰٬۰۰۰ دور) کلید اصلی را می‌سازد؛ فهرست اتاق‌ها با AES-256-GCM زیر همین کلید است. هر اتاق فایل جداگانه‌ای دارد که با کلیدی مشتق از رمز خودِ همان اتاق رمز شده است، پس بدون رمز اتاق حتی با رمز برنامه هم پیام‌ها خوانده نمی‌شوند.
- **اثر انگشت از راه Keystore.** کلید اصلی با کلید AES سخت‌افزاری (در صورت وجود StrongBox) پیچیده می‌شود که فقط با احراز هویت بیومتریک قوی باز می‌شود و با تغییر اثر انگشت‌های ثبت‌شده باطل می‌گردد.
- **قفل خودکار، قفل با خاموش شدن صفحه، پاک شدن پس از چند رمز اشتباه، رمز اضطراری** که همه‌چیز را بی‌سروصدا پاک می‌کند، مسدود کردن اسکرین‌شات (و خبر دادن به طرف مقابل در اندروید ۱۴+)، کیبورد بی‌حافظه، پاک شدن خودکار کلیپ‌بورد، حذف EXIF از عکس‌ها پیش از ارسال، بدون پشتیبان‌گیری ابری، فقط گواهی‌های سیستم.
- **اعلان قابل تنظیم.** چهار صدای اختصاصی، صدای سیستم (با انتخاب‌گر زنگ اندروید) یا بی‌صدا، به‌علاوه‌ی چهار الگوی لرزش. چون اندروید صدای کانال را قفل می‌کند، با هر تغییر کانال تازه‌ای ساخته می‌شود. متن پیام هرگز در اعلان نمایش داده نمی‌شود.
- **پس‌زمینه.** به‌طور پیش‌فرض یک کار زمان‌بندی‌شده هر ۱۵ دقیقه تاریخچه را می‌کشد؛ با روشن کردن «اتصال پس‌زمینه» یک سرویس پیش‌زمینه سوکت را زنده نگه می‌دارد تا پیام‌ها بی‌درنگ برسند.

اگر نجوا را روی دامنه‌ی دیگری نصب می‌کنید، `HOST` را در `android/app/src/main/java/com/najvaa/app/net/Relay.kt` به همان دامنه تغییر دهید.

### ساخت APK

پیش‌نیاز: JDK 21 و Android SDK 36 (platform 36 و build-tools 36). حداقل اندروید ۸ (API 26).

```powershell
$env:JAVA_HOME = "C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot"
cd android
.\gradlew.bat assembleDebug
```

خروجی: `android/app/build/outputs/apk/debug/app-debug.apk`. نسخه‌ی انتشار با `assembleRelease` ساخته می‌شود (کوچک‌سازی و R8 فعال است) و باید با کلید خودتان امضا شود.

### اولین اجرا

۱. سه صفحه‌ی معرفی، سپس ساخت رمز برنامه (دست‌کم ۸ نویسه) و فعال‌سازی اختیاری اثر انگشت.
۲. در «گفتگوها» با دکمه‌ی + یک اتاق بسازید (کد هفت‌رقمی و رمز اتاق جداگانه کپی/ارسال می‌شوند) یا با کد و رمزی که برایتان فرستاده‌اند وارد شوید. ورود اول از سرور می‌پرسد؛ رمز اشتباه رد می‌شود و اتاق خالی ساخته نمی‌شود.
۳. نگه‌داشتن انگشت روی هر اتاق: اطلاعات، سنجاق، بی‌صدا، پاک کردن از گوشی. در اطلاعات اتاق: ارسال کد و رمز، نام من، زمان حذف خودکار، دستگاه‌های متصل با شماره‌ی امنیتی، فضای سرور، پاک کردن برای هر دو.

## پیش از نصب

1. یک سرور دبیان ۱۲ یا ۱۳ با دسترسی root.
2. دامنه را به کلادفلر اضافه کنید و nameserverهای ثبت‌کننده‌ی دامنه را روی دو nameserver کلادفلر بگذارید.
3. در کلادفلر یک **API Token** بسازید (My Profile ← API Tokens ← Create Token ← Create Custom Token) با این دسترسی‌ها:

   | بخش | دسترسی | سطح | برای |
   |---|---|---|---|
   | Zone | Zone | Read | پیدا کردن دامنه |
   | Zone | DNS | Edit | ساخت رکوردها و به‌روزرسانی خودکار IP |
   | Zone | Zone Settings | Edit | SSL سخت‌گیرانه، HTTPS اجباری، TLS 1.2 به بالا |
   | Zone | SSL and Certificates | Edit | ساخت گواهی Origin پانزده‌ساله |
   | Account | Access: Apps and Policies | Edit | محافظت پنل با کد یک‌بارمصرف ایمیلی |
   | Account | Access: Organizations, Identity Providers, and Groups | Edit | روشن کردن ورود با کد ایمیلی |
   | Account | Calls (Realtime) | Edit | (اختیاری) ساخت خودکار کلید TURN برای تماس |

   در Zone Resources دامنه‌ی خودتان و در Account Resources حساب خودتان را انتخاب کنید.
4. (برای پنل) اگر Zero Trust کلادفلر را هنوز فعال نکرده‌اید، نصب‌کننده خودش می‌گوید که one.dash.cloudflare.com را باز کنید، یک نام تیم و پلن رایگان انتخاب کنید و برگردید.

## نصب

از کامپیوتر خودتان بسته را به سرور بفرستید (فایل `najva-package.tar.gz` کنار همین پوشه است):

```bash
scp najva-package.tar.gz root@SERVER:/root/
```

بعد روی سرور:

```bash
cd /root && tar -xzf najva-package.tar.gz && bash najva-package/install.sh
```

## سؤال‌هایی که نصب‌کننده می‌پرسد

1. **دامنه‌ی چت**، مثلاً `example.com`. چت روی خود دامنه باز می‌شود و `www` به آن هدایت می‌شود.
2. **توکن کلادفلر.** موقع تایپ دیده نمی‌شود؛ در اجراهای بعدی با زدن Enter همان توکن قبلی می‌ماند.
3. **آدرس‌های سرور.** IPv6 و IPv4 را خودش پیدا می‌کند و می‌پرسد کدام منتشر شود. پشت CGNAT (مثل استارلینک) فقط IPv6 کار می‌کند.
4. **تماس صوتی.** ساخت خودکار کلید TURN کلادفلر، یا وارد کردن دستی آن.
5. **فضای تاریخچه.** سقف حجم (پیش‌فرض ۵۰ گیگ) و مدت نگه‌داری (پیش‌فرض ۹۰ روز).
6. **پنل مدیریت.** نصب بشود یا نه، آدرسش (پیش‌فرض `mod.دامنه`)، ایمیل ادمین و (اختیاری) لایسنس Nova.

بعد یک خلاصه نشان می‌دهد و با تأیید شما شروع می‌کند.

## کارهایی که خودکار انجام می‌شود

- نصب nginx، Node.js و (برای پنل) PHP.
- نصب سایت و رله؛ رله با کاربر موقت سیستمی و محدودیت‌های امنیتی systemd اجرا می‌شود.
- ساخت گواهی Origin کلادفلر (۱۵ ساله) با کلیدی که فقط روی همین سرور ساخته می‌شود.
- nginx فقط به آدرس‌های کلادفلر جواب می‌دهد، پس IP سرور پنهان می‌ماند. لاگ دسترسی چت خاموش است.
- رکوردهای DNS (پروکسی‌شده) برای دامنه، `www` و پنل. اگر رکوردی از قبل به جای دیگری اشاره کند، قبل از تغییر می‌پرسد.
- تنظیمات دامنه: SSL روی Full (strict)، HTTPS اجباری، حداقل TLS 1.2، TLS 1.3 و WebSocket.
- به‌روزرسانی خودکار IP هر ۵ دقیقه.
- پنل:
  - Cloudflare Access فقط برای ایمیل شما، با کد یک‌بارمصرف.
  - کاربر سیستمی جدا و PHP-FPM اختصاصی.
  - دیتابیس SQLite و زمان‌بند.
  - در پایان، ساخت حساب ادمین (رمز را خودتان وارد می‌کنید).
- بررسی نهایی: سایت از طریق کلادفلر باز می‌شود و پنل پشت Access است.

## بعد از نصب

- **چت:** `https://دامنه`
- **پنل:** `https://mod.دامنه`
  1. ایمیل را وارد کنید و کدی را که کلادفلر می‌فرستد بزنید.
  2. با حساب پنل وارد شوید.
  3. در «حساب من» ورود دومرحله‌ای یا passkey را روشن کنید. تا این کار را نکنید، بقیه‌ی پنل باز نمی‌شود.
- **فراموشی رمز پنل:**

```bash
cd /var/www/mod.DOMAIN && sudo -u najvapanel php artisan najva:password EMAIL
```

### پنل مدیریت و پاسخگویی قضایی

پنل در ریشه‌ی `mod.دامنه` است (چیدمان پیام‌رسان: نوار بخش‌ها، فهرست، گفتگو، اطلاعات). ورود، دومرحله‌ای و passkey همچنان در صفحه‌های Nova (`/console`) است. محتوای گفتگوها همیشه رمزنگاری سرتاسری است؛ پنل فقط زمان، حجم، شناسه و پرچم‌ها را می‌بیند.

- **اتاق‌ها:** جستجو با کد ۷ رقمی، خط زمانی موارد ذخیره‌شده، قطع اتصال، مسدودی (کد 4012 در اپ)، بازنشانی، حذف.
- **پرونده‌های حقوقی:** ثبت درخواست مرجع (نوع، مرجع، شماره‌ی نامه، مهلت، مسئول)، پیوند اتاق‌ها، تاریخچه‌ی گفتگومانند، یادداشت‌ها. متن‌ها با کلید پنل رمزشده ذخیره می‌شوند.
- **حفظ داده (توقیف):** با استناد به پرونده؛ از آن لحظه حذف کاربر، حذف خودکار، سقف حجم و سقف زمانی هیچ چیزی را پاک نمی‌کنند (به `held/` منتقل می‌شود) و حذف اتاق ممکن نیست.
- **پایش اتصال:** فقط برای یک اتاق، با پرونده و حداکثر ۹۰ روز: زمان، IP، کشور، شناسه‌ی دستگاه و مرورگر هر اتصال و هر ارسال. هیچ اتاق دیگری ثبت نمی‌شود.
- **بسته‌ی افشا:** ZIP رمزدار AES-256 (رمز یک‌بار نشان داده می‌شود) با `manifest.json`، `entries.csv`، `connections.csv`، در صورت نیاز فایل‌های رمزشده، `SHA256SUMS` و امضای HMAC. بررسی: `php artisan najva:verify-export DIR`. پس از ۷ روز پاک می‌شود.
- **گزارش تخلف:** فرم عمومی `https://دامنه/report.html`؛ گزارش‌های کودکان، تروریسم و تهدید بالای صف.
- **مسدودی IP/CIDR**، **اعلان سراسری** در همه‌ی اپ‌ها، **گزارش شفافیت** شش‌ماهه/سالانه با CSV.
- **امنیت:** نقش‌ها (مدیر ارشد، مسئول حقوقی، ناظر محتوا، فقط مشاهده)، تأیید دوباره‌ی رمز و کد برای کارهای حساس، خروج پس از ۱۵ دقیقه بی‌کاری، نشست وابسته به مرورگر و IP، CSP سخت‌گیرانه، محدودیت نرخ، لاگ ممیزی با زنجیره‌ی هش و دکمه‌ی بررسی یکپارچگی.

تنظیمات اختیاری در `.env` پنل: `NAJVA_IDLE_MINUTES`، `NAJVA_BIND_IP`، `NAJVA_STEPUP_MINUTES`، `NAJVA_EXPORT_DAYS`، `NAJVA_EXPORT_MAX_MB`، `NAJVA_WATCH_MAX_DAYS`.

## به‌روزرسانی

نسخه‌ی جدید بسته را روی سرور باز کنید و دوباره `bash najva-package/install.sh` را بزنید. جواب‌های قبلی پیش‌فرض می‌شوند (فقط Enter بزنید). رمزها، گواهی، تاریخچه‌ی رمزشده و دیتابیس پنل دست نمی‌خورند.

## جای چیزهای مهم روی سرور

| چیز | مسیر |
|---|---|
| تنظیمات و رمزهای رله | `/etc/najva/relay.env` (فقط root) |
| توکن کلادفلر و تنظیم DDNS | `/etc/najva/cf.env` (فقط root) |
| گواهی Origin | `/etc/ssl/najva/` |
| تاریخچه‌ی رمزشده‌ی چت | `/var/lib/najva` |
| پنل | `/var/www/mod.DOMAIN` (رمزهایش در `.env`) |
| لاگ نصب | `/var/log/najva-install.log` |
| سرویس‌ها | `najva-relay`، `najva-ddns.timer`، `najva-panel-scheduler.timer` |

## ساخت دوباره‌ی فیلتر صدا (فقط اگر سورس آن را تغییر دهید)

```bash
node chat/voicefx-src/build-voicefx.mjs
```

خروجی‌اش `chat/public/voicefx-worklet.js` است (در سورس اصلی هم `node deploy/build-voicefx.mjs`).
